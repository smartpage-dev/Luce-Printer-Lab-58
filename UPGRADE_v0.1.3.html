Android lint fix / 保留 API 26 支援

SOURCE UPDATE / NO APK INCLUDED

1. 今次唔係舊 Java 錯誤

你提供嘞新日誌已通過 Java 編譯、單元測試同 APK 組裝。但最後嘞 Android lint 報錯：

android:windowLightNavigationBar requires API level 27
(current min is 26) [NewApi]

該屬性現在只放在 values-v27。保留 API 26、藍牙、打印、資料庫及簽署設定；唔會關掉 lint 或略過錯誤。

舊 run 雖然組裝過 APK，但後續驗證及 APK artifact 發佈已跳過。日誌 ZIP 唔係安裝檔。

2. 更新原本 repository

  1. 使用 v0.1.3 Patch From v0.1.2。只適用於已提交 v0.1.2 的 Luce-Printer-Lab-58，唔係 LensDrop repository。
  2. 解壓，打開內層資料夾。GitHub 選 Add file > Upload files，將內容放去 repository 根目錄，保留路徑、覆蓋同名檔案。唔好先刪除 app，唔好只上傳 ZIP，唔好多包一層資料夾。
  3. GitHub Desktop 使用者請逐檔合併更新，保留原本 app 內其他檔案，再 Commit / Push。唔改密鑰或 Secrets。
  4. Commit message 可用 Fix API-qualified theme - Printer Lab v0.1.3。

更新後必須同時有這兩個檔案：

app/src/main/res/values/styles.xml
app/src/main/res/values-v27/styles.xml

打開 app/build.gradle，確認：

versionCode 4
versionName '0.1.3-lab'

需要重新建立完整來源碼時，才用 Full GitHub-ready ZIP。Patch 與 Full 二選一。

3. 開一個新 build

Actions > Printer Lab Android APK > Run workflow

選已更新的分支，通常係 main；確認 SDK licenses，signing mode 沿用原本選擇。

唔好按舊 run 內的 Re-run jobs。GitHub 重跑會沿用舊 commit，唔會自動用新修正。

成功後下載 PrinterLab58-APK-...，內有 PrinterLab58-debug.apk。BUILD_INFO.json 應顯示 0.1.3-lab、version code 4 同新 commit。

仍失敗時保留新日誌。詳細 lint HTML/XML 在另一個 PrinterLab58-logs-... artifact，唔係一般執行日誌 ZIP。
